# RAGの「チャンク職人」を卒業せよ。推論ベースの破壊者『PageIndex』が描く検索の終焉

「RAGを作ってみたが、期待した答えが返ってこない」
「チャンクサイズの微調整に、もう人生の貴重な時間を溶かしたくない」

そんなエンジニアたちの悲鳴が、GitHubから聞こえてくるようだ。これまで我々は、ドキュメントを強引に切り刻み（チャンキング）、多次元空間に放り込み（ベクトル化）、似たような断片を拾い上げることに心血を注いできた。だが、その努力は本当に報われているだろうか？

今、その「当たり前」を根底から覆すプロジェクトが産声を上げた。その名は **『PageIndex』** 。

従来の「ベクトル検索＋チャンク分割」という力技を捨て、AlphaGoのように**推論ベースで情報を探索する**。まさに、RAGという手法における「パラダイムシフト」が起きようとしている。なぜ、このプロジェクトがエンジニアの心を掴んで離さないのか。その真価を解剖していこう。

### 「似ている」から「理解している」へ。PageIndexがヤバい4つの理由

PageIndexがこれまでのRAGと決定的に一線を画すのは、情報の探し方が「直感（ベクトル）」ではなく「論理（推論）」に基づいている点だ。

- **ベクトルDBからの解放**: 近似検索（ANN）に頼らないため、煩わしいDBの管理やインデックスの再構築に頭を悩ませる必要はない。
- **「チャンク分割」という呪縛の消失**: 文脈を無視してテキストをぶった切る作業はもう不要だ。ドキュメントをページやセクションといった「人間が理解する単位」のまま扱うことができる。
- **エージェントによる思考の探索**: まるで熟練の司書が目次を眺め、関連するページをめくるように、LLMがインデックスツリーを能動的に辿っていく。
- **狂気的なまでの精度（98.7%）**: 金融ドキュメントのベンチマーク「FinanceBench」において、驚異のスコアを叩き出した。回答にはソースとなるページ番号が明記されるため、AI特有の「嘘（ハルシネーション）」を見逃さない。

### その舞台裏：情報の森を「歩く」アルゴリズム

PageIndexの動作は、静的な検索ではない。それは、ドキュメントという名の迷宮を攻略する「冒険」に近い。

1.  **ツリーインデックスの構築**: まず、ドキュメントを「目次」のような階層構造へと再構成する。これが探索のための地図となる。
2.  **推論による動的探索**: LLMがエージェントとして振る舞い、質問の意図を汲み取りながら、この地図（ツリー）を一段ずつ降りていく。

「単語が似ている場所」を探すのではなく、「答えがあるべき場所」を推論して見つけ出す。この差が、回答の質に決定的な違いをもたらすのだ。💾

### 導入は一瞬。MCP対応がもたらす自由

PageIndexは、現代のエンジニアが何を求めているかを熟知している。最近話題の **MCP（Model Context Protocol）** にも対応済みだ。

つまり、あなたが普段使っているClaude DesktopやCursorに、この「最強の脳」を即座にインストールできるということだ。長大なPDFを読み込ませ、爆速で正解に辿り着く快感。それは一度味わうと、もう元には戻れない。

```bash
# PageIndexをMCP経由で利用する例（npxを使用）
npx @vectify/pageindex-mcp
```

APIも提供されているため、既存の自社サービスへ「推論型RAG」を組み込むことも極めて容易だ。🔥

### PageIndexが真価を発揮する瞬間

- **金融・法務の迷宮**: 数百ページに及ぶ有価証券報告書や、複雑に入り組んだ契約書から、たった一つの正確な数値を導き出す。
- **巨大な技術ドキュメント**: 膨大な仕様書の中から、特定の条件下での振る舞いをピンポイントで特定する。
- **曖昧な社内ナレッジ**: 抽象的な問いかけに対し、文脈を補完しながら「本当に知りたかったこと」を提示する。

### 辛口評価：PageIndexの光と影

**Pros（光）:**
- 精度が圧倒的。特にコンテキストが重要な長文読解において、右に出るものはいない。
- 構築のシンプルさ。ベクトルDBのパラメータに一喜一憂する日々が終わる。
- Vision-based RAGとしての可能性。OCRに頼らず、図表を含めた構造理解が可能だ。

**Cons（影）:**
- 探索のたびにLLMが推論を繰り返すため、従来のベクトル検索と比較してトークンコストと応答時間は増える傾向にある。速度よりも精度を重視する局面でこそ、その牙を剥く。
