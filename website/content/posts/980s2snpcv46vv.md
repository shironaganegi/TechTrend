# 「Pythonは遅い」という呪縛を解く。2024年にエンジニアが向き合うべき「真の速度」とは？

「Pythonは遅い」。
この言葉は、エンジニアの世界で一種の“定説”のように語り継がれてきました。C++やRustといった「速い」言語と並べられ、肩身の狭い思いをした経験がある人も多いでしょう。しかし、データサイエンスが当たり前となり、AIがインフラ化した現代において、その評価はあまりにも表面的なものだと言わざるを得ません。

もしあなたが「速度」を理由にPythonを避けているとしたら、それはもったいない話です。この記事を読み終える頃、あなたは「実行速度」という名の呪縛から解き放たれ、プロジェクトを成功に導くための「本当の武器」を手に入れることになるはずです。

### なぜPythonは「鈍足」というレッテルを貼られたのか

なぜ、Pythonは他のコンパイル言語の後塵を拝するのか。その理由は、この言語の「性格」にあります。

- **動的型付けと逐次解釈**: 実行中に「このデータは何型か？」といちいち確認しながら進むインタプリタ方式は、いわばフルマラソンを地図なしで走り、曲がり角ごとに立ち止まって確認するようなものです。
- **GIL（グローバル・インタプリタ・ロック）の壁**: 1つの調理場に1人の料理人しか立てないような制限です。たとえCPUがマルチコアでも、一度に1つのスレッドしか動かせないこの仕組みが、並列処理のボトルネックとなってきました。
- **メモリ管理の贅沢さ**: 自由度が高い反面、裏側では頻繁にメモリの確保と破棄が行われています。これは、高級料亭で一皿ごとに箸を使い捨てるようなコストを支払っているイメージです。

### モダンPythonは、すでに「脱皮」を始めている

しかし、これらは「昔の常識」になりつつあります。現代のPythonエコシステムは、この弱点を克服するための驚くべき進化を遂げました。

- **「外注」による高速化**: NumPyやPandasといったライブラリのコアは、実はC言語やC++で書かれています。Pythonは「指示出し」に徹し、重たい計算は専門のプロ（C言語）に丸投げする。この賢い役割分担が、圧倒的なパフォーマンスを生むのです。
- **Faster CPythonプロジェクトの衝撃**: バージョン3.11以降のPythonは、もはや別物です。エンジンそのものの改良により、特別な工夫をしなくても10～60%の高速化を実現しています。
- **JITコンパイラの魔術**: Numbaなどのツールを使えば、実行時にPythonコードを機械語へダイレクトに変換できます。特定の処理においては、C言語に肉薄する速度を叩き出すことすら可能です。

### ほんの数行で変わる、パフォーマンスの境界線

コードの書き方一つで、Pythonはその表情を変えます。

```python
import timeit

# 昔ながらの泥臭いループ
def loop_test():
    res = []
    for i in range(1000):
        res.append(i * 2)
    return res

# 洗練されたリスト内包表記
def comprehension_test():
    return [i * 2 for i in range(1000)]

print(f"Loop: {timeit.timeit(loop_test, number=10000):.4f}s")
print(f"Comprehension: {timeit.timeit(comprehension_test, number=10000):.4f}s")
```

リスト内包表記を使う。ただそれだけで、処理は劇的にスマートになります。道具をどう使いこなすか、それこそがエンジニアの腕の見せ所でしょう。
